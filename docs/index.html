Which Pages Should an Editor Review First? A Client-Grouped Evaluation of a Decision-Support Review Queue

Muhammad Sulaiman · Code & notebooks · Built on the FlyRank ML Internship dataset
Abstract

An editor can review only a handful of pages a week, so the decision this work supports is the order of that review, measured by Precision@50, fixed before any training. Using 30,000 pseudonymized pages from 32 clients, I compared two transparent rules with four learned models on identical five-fold splits grouped by client, so every score comes from clients the model never saw. The learned models ranked the queue clearly better than both rules (Precision@50 0.77–0.78 versus 0.60 and 0.46; random order 0.54), yet were indistinguishable from each other, so the readable Logistic Regression — the only model ahead of the hand rule in all five folds — drives the final queue. A stricter test on the full warehouse with a genuine future-window label found a much weaker honest signal (ROC AUC 0.60), which is the main limitation. The output is a ranked review queue with reason codes and suggested actions: decision support, not a causal claim about refreshes or a model of Google's ranking.

1. Introduction and problem

When a page starts losing search traffic, nobody notices until it has already cost visits. A content team cannot check every page, so the practical question is not "will this page decline?" in the abstract but "which fifty pages should a person look at first?" This paper evaluates a ranking for that review queue the way it would be used: on websites the model has never seen, against simple rules a team could write by hand.

Unit: one page. Output: a ranked queue, each page with a score, reason codes a human can check, and one suggested action. Metric: Precision@50 — of the 50 pages placed first, the share that are really declining — plus P@20, P@100, ROC AUC and average precision. Cost of an error: a false alarm wastes an editor's time; a miss lets a valuable page keep losing traffic. Because capacity is the constraint, the top of the list matters most.

2. Data

Primary — starter release. 30,000 pseudonymized content pages from 32 clients, one row per page, with trailing-90-day search and analytics signals (impressions, clicks, CTR, average position, sessions, engagement, age, freshness, length, intent, type). The grain was checked: every page identifier is unique. 54.2% of pages are labelled declining.

Validation — warehouse release (FlyRank internship warehouse on Hugging Face, build v20260703). I used the daily performance table for the mid-panel month March 2026 only — 9,841,378 page-day rows from 55 clients — and the client table for history depth. The final month (June 2026) was deliberately left untouched as a sealed test window.

Labels. Starter: the page's current trend is "down" — a proxy. Warehouse: a genuine future-window label — the page's daily impressions in March 16–31 fell more than 20% below its March 1–15 average (pages with at least 50 impressions in March 1–15: 92,548 pages, 32.7% declined).

Excluded, and why. The trend columns the label is built from (they would hand the model the answer); page and client identifiers (pseudonyms, used only for grouping and splitting); any value from March 16–31 as a warehouse feature (it is the future at the decision moment); and GA4 session columns on the warehouse (available on only 4.2% of March rows and zero-filled elsewhere). Neither release contains client names, domains, URLs, titles or search queries, and none appear in this paper.

3. Methodology

Assumption. A page trending down now is a reasonable stand-in for "worth reviewing"; the warehouse future-window label tests whether that holds forward in time.

Features (starter). 18 numeric signals — search volume, competition, CPC, word and character count, log-transformed 90-day impressions, clicks, sessions and AI sessions, days with impressions and with sessions, content age, days since last update, CTR, average position, engagement rate, scroll rate and AI-traffic share — plus four categorical ones (competition level, content type, intent, position tier), 35 columns after one-hot encoding. A code assertion confirms the label columns are absent.

Baselines (no training). (1) Hand rule: pages not updated for 180+ days that still get 500+ impressions, ranked by impressions. (2) Weighted rule from the reference pipeline: 0.40 × visibility + 0.30 × freshness risk + 0.25 × position opportunity + 0.05 × depth gap. Models: Logistic Regression, a depth-4 Decision Tree, Random Forest and Gradient Boosting, all with fixed seeds.

Validation design. Five-fold GroupKFold on the client identifier: no client appears in both training and test in any fold (checked in code). Every baseline and model is scored on exactly the same folds. Scores used for the final queue are out-of-fold: each page is scored by a model that never saw its client.

Leakage checks. Label columns asserted absent; on the warehouse I added one label-window column on purpose, measured how far it inflated the score, then removed it.

All three stronger models beat both rules by 0.17–0.32 at Precision@50, and beat random order by about 0.23. The differences between them (0.768–0.784) are far smaller than how much each one swings from fold to fold (standard deviation 0.12–0.15), so this evaluation cannot say one is better than another. More complexity did not earn more credit: plain Logistic Regression is as good as the ensembles here. The depth-4 tree only ties the hand rule.

4.2 What the models lean on

Read together with Logistic Regression's coefficients — the largest are impressions (positive) and clicks (negative) — the pattern is: pages that are visible but rarely clicked, and younger pages, were more often declining in this sample. That matches the early discovery that declining pages are younger (median 216 days) than growing ones (292). On one held-out fold the top 50 held 41 declining pages and 9 false alarms, all of which were actually trending up or stable — the model cannot yet tell a young page that is falling from one that is still climbing.

4.3 A true future-window label is much harder

Predicting whether a page's impressions will fall over the next two weeks from only the previous two weeks of search signals is far harder than recognising a page whose current trend is already down. The leak experiment shows why a too-good number deserves suspicion before celebration.

5. Limitations and honest framing

  • Proxy label. The main results use the current trend, not a future outcome: they show which pages look like declining pages now. With a true future label the honest signal is much weaker (ROC AUC 0.60).
  • No causal claim. Nothing here shows that refreshing a page causes recovery, or reveals how Google ranks pages. Results are observed, directional and meant for decision support.
  • Models are not separable. The stronger models differ by less than their fold-to-fold spread; the finding is "learned beats rules", not "this model beats that one".
  • Low CTR is not proof of a bad title. The queue is dominated by visible, rarely clicked pages; a search-page feature (answer box, AI overview) may be taking those clicks. The action is a review, not a rewrite order.
  • Thin, unbalanced history. Only 3 of 104 warehouse clients have 12+ months of search history and 37 have no search start date, so seasonality cannot be checked. One starter fold is a single large client.
  • Pooled scores. The final queue pools out-of-fold scores from five models; their probability scales are similar but not identical.

6. Ranked recommendations

How an editor would use it tomorrow.

  1. Work the queue from the top, about 50 pages per review cycle; pages marked high confidence (score ≥ 0.70 and ≥ 500 impressions) first.
  2. For low_ctr_visible pages, first look at the live search page: if an answer box or AI overview takes the clicks, note it and move on; otherwise rewrite the title and meta description to match the query intent.
  3. For pages slipping beyond position 20, check whether the content still matches what searchers want and add internal links from stronger pages.
  4. Re-score monthly and compare: the honest future-window result says to treat the queue as a prioritised shortlist for human judgement, not an automatic decision.
